# Running the Direct Ollama API

This guide explains how to verify the **direct Ollama API** independently of FastAPI, Google ADK, and MCP.

This path is useful for confirming that the configured Ollama server and Qwen3 model are working directly.

## 1. Execution Flow

The direct API path is:

```text
PowerShell / HTTP Client
        ↓
Ollama HTTP API
        ↓
Qwen3 8B
```

This is different from the FastAPI path:

```text
Client
  ↓
FastAPI
  ↓
ADK
  ↓
Agent
  ↓
LiteLLM
  ↓
Ollama
  ↓
Qwen3 8B
```

It is also different from the independent MCP path:

```text
MCP Client
  ↓
MCP Server
  ↓
ask_question
  ↓
LiteLLM
  ↓
Ollama
  ↓
Qwen3 8B
```

---

## 2. Prerequisites

Make sure Ollama is installed and running.

From PowerShell, verify the installed models:

```powershell
ollama list
```

Expected model:

```text
qwen3:8b
```

The Ollama API is expected at:

```text
http://localhost:11434
```

You do not need to start FastAPI or the MCP server for this test.

---

## 3. Verify Ollama Is Reachable

Run:

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://localhost:11434/api/tags"
```

A successful response should contain the installed models, including:

```text
qwen3:8b
```

This verifies that the Ollama HTTP API is reachable.

---

## 4. Send a Direct LLM Question

Use the Ollama `/api/chat` endpoint.

Example:

```powershell
$response = Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:11434/api/chat" `
  -ContentType "application/json" `
  -Body '{"model":"qwen3:8b","messages":[{"role":"user","content":"What is law?"}],"stream":false}'
```

Display the complete response:

```powershell
$response | ConvertTo-Json -Depth 20
```

---

## 5. Extract the Answer

To display only the model answer:

```powershell
$response.message.content
```

Expected output will be a generated explanation of law.

The exact wording can differ because the answer is generated by Qwen3.

---

## 6. Verify the Model

Run:

```powershell
$response.model
```

Expected:

```text
qwen3:8b
```

This confirms that the request was handled by the expected Ollama model.

---

## 7. Complete Direct API Example

The following can be copied as one block:

```powershell
$response = Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:11434/api/chat" `
  -ContentType "application/json" `
  -Body '{"model":"qwen3:8b","messages":[{"role":"user","content":"What is law?"}],"stream":false}'

Write-Host ""
Write-Host "=============================================="
Write-Host "DIRECT OLLAMA API TEST"
Write-Host "=============================================="
Write-Host ""

Write-Host "Question:"
Write-Host "What is law?"
Write-Host ""

Write-Host "Model:"
Write-Host $response.model
Write-Host ""

Write-Host "Answer:"
Write-Host $response.message.content
Write-Host ""

Write-Host "=============================================="
```

---

## 8. Verify the Raw Response

For troubleshooting or detailed inspection:

```powershell
$response | ConvertTo-Json -Depth 20
```

The response should contain fields similar to:

```text
model
created_at
message
done
```

The answer is contained under:

```text
message.content
```

The model name is contained under:

```text
model
```

## 10. Direct API vs FastAPI Test

### Direct Ollama API

```text
PowerShell
    ↓
Ollama /api/chat
    ↓
Qwen3 8B
```

### FastAPI

```text
PowerShell
    ↓
FastAPI /sessions/.../messages
    ↓
ADK
    ↓
Agent
    ↓
LiteLLM
    ↓
Ollama
    ↓
Qwen3 8B
```

If the direct Ollama API works but the FastAPI request fails, the problem is likely in the application/ADK/LiteLLM path rather than Ollama itself.

If the direct Ollama API also fails, troubleshoot Ollama/model availability first.

---

## 11. Direct API Verification Checklist

Use this sequence:

```text
1. Confirm Ollama is running
2. Run ollama list
3. Confirm qwen3:8b exists
4. Call /api/tags
5. Call /api/chat
6. Verify response.model = qwen3:8b
7. Verify response.message.content contains an answer
```

---

## 12. Common Issues

### Ollama connection refused

If you receive a connection error for:

```text
http://localhost:11434
```

make sure Ollama is running.

Then retry:

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "http://localhost:11434/api/tags"
```

### Model not found

Run:

```powershell
ollama list
```

If `qwen3:8b` is not listed, the configured model is not available locally.

### Empty answer

Inspect the complete response:

```powershell
$response | ConvertTo-Json -Depth 20
```

Do not rely only on `message.content` when troubleshooting.

### FastAPI is running

That does not affect the direct Ollama API test because Ollama uses port `11434`, while the project FastAPI/MCP runtime uses port `8000`.

Therefore, FastAPI can remain running during this specific direct Ollama test.

---

## 13. Configuration Used by the Project

The project configuration is:

```text
OLLAMA_API_BASE=http://localhost:11434
OLLAMA_MODEL=qwen3:8b
```

For the direct Ollama test, these values correspond to:

```text
API:
http://localhost:11434/api/chat

Model:
qwen3:8b
```

Do not change `.env` as part of this verification.

---

## 14. What This Test Proves

A successful direct API request proves:

```text
Ollama server
        ↓
Ollama HTTP API
        ↓
qwen3:8b
        ↓
Generated response
```

It does **not** by itself validate:

- Google ADK
- FastAPI routing
- ADK sessions
- ADK agent delegation
- MCP
- LiteLLM integration

Those components are validated separately by the project's FastAPI, ADK, and MCP tests.

---

## 15. Recommended Overall Verification Order

For troubleshooting the complete project, use this order:

```text
1. Direct Ollama API
       ↓
2. Independent MCP LLM
       ↓
3. FastAPI / ADK LLM
       ↓
4. Full integration/e2e tests
```

This makes it easier to identify which layer is responsible for a failure.
