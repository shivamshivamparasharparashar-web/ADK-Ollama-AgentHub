# MCP Server & Independent LLM Testing Guide

This guide explains how to run and verify the MCP interface of **ADK-Ollama-AgentHub**, including the independent MCP LLM answering capability.

The MCP layer is independent of the ADK agent execution path:

```text
MCP Client / Test
       |
       v
MCP Server
       |
       v
LiteLLM
       |
       v
Ollama
       |
       v
Qwen3 8B
```

The MCP server continues to expose the existing utility tools and now also exposes:

- `mcp_health`
- `get_server_time`
- `add_numbers`
- `multiply_numbers`
- `ask_question` — independently sends a question to the configured Ollama LLM

---

## 1. Prerequisites

From the project root:

```powershell
cd D:\ADK-Ollama-AgentHub\ADK-Ollama-AgentHub
```

Activate the virtual environment:

```powershell
.\.venv\Scripts\Activate.ps1
```

Verify Ollama is available:

```powershell
ollama list
```

The configured model is:

```text
qwen3:8b
```

The existing `.env` configuration is used. No additional MCP-specific environment variables are required.

---

# 2. Start the MCP Server

Open **Terminal 1** and run:

```powershell
python -m app.mcp.server
```

Expected startup output includes:

```text
StreamableHTTP session manager started
INFO: Application startup complete.
INFO: Uvicorn running on http://127.0.0.1:8000
```

The MCP endpoint is:

```text
http://127.0.0.1:8000/mcp
```

### Important

Do **not** open `/mcp` directly in Chrome as if it were a normal web page.

The MCP endpoint is intended to be accessed by an MCP client.

Also note that the MCP server uses port `8000`, so do not run the FastAPI server or another application on the same port at the same time.

---

# 3. Verify MCP Tool Discovery

Keep Terminal 1 running.

Open **Terminal 2**:

```powershell
pytest -q tests/integration/test_mcp_integration.py
```

Expected result:

```text
1 passed
```

This verifies that the MCP client can connect to the server and discover the available MCP tools.


Expected result:


# 5. Verify Multi-Agent MCP Delegation

Run:



This verifies the existing ADK multi-agent flow, including delegation to the MCP agent.

This is separate from independent MCP LLM answering.

# 6. Independent MCP LLM Answering

The MCP server now exposes:

```text
ask_question(question)
```

This tool does **not** send the question through the ADK root agent.

Instead:

```text
MCP Client
    |
    v
ask_question()
    |
    v
LiteLLM
    |
    v
Ollama
    |
    v
qwen3:8b
```

This allows the MCP layer to answer questions independently.

---

# 7. Runtime Question

The question should be supplied at runtime rather than hard-coded in the test/client.

Example:

```powershell
python tests/integration/test_mcp_llm_answer.py "What is law?"
```

Another example:

```powershell
python tests/integration/test_mcp_llm_answer.py "Explain quantum computing"
```

Another:

```powershell
python tests/integration/test_mcp_llm_answer.py "What is SAP?"
```

The MCP server receives the supplied question through:

```text
ask_question
```

and returns:

```text
question
model
answer
```

---

# 8. Example: Ask "What is law?"

Start the MCP server in Terminal 1:

```powershell
python -m app.mcp.server
```

Then in Terminal 2:

```powershell
python tests/integration/test_mcp_llm_answer.py "What is law?"
```

Expected output format:

```text
Question:
What is law?

Model:
qwen3:8b

Answer:
<answer generated by the Ollama Qwen3 model>
```

The exact answer will be generated by the local model and may vary between executions.

---

# 10. Important: MCP Tool Is Not a PowerShell Command

This will **not** work:

```powershell
ask_question("What is law?")
```

PowerShell will report that `ask_question` is not recognized.

That is expected.

`ask_question` is an MCP tool, not a PowerShell function.

The correct approach is to use an MCP client/test:

```powershell
python tests/integration/test_mcp_llm_answer.py "What is law?"
```

# 12. MCP Server Port Conflict

The MCP server uses:

```text
127.0.0.1:8000
```

Therefore, do not run these simultaneously on the same port:

```text
MCP server
FastAPI server
```

For example, if MCP is running:

```powershell
python -m app.mcp.server
```

do not also start:

```powershell
uvicorn app.api.main:app --host 127.0.0.1 --port 8000
```

Stop the MCP server with:

```text
Ctrl+C
```

before starting another service on port 8000.

# 14. What Each Test Proves

| Test / Command | Purpose |
|---|---|
| `test_mcp_integration.py` | MCP server connectivity and tool discovery |
| `test_mcp_tool_invocation.py` | Actual MCP tool invocation |
| `test_multi_agent_delegation.py` | ADK multi-agent delegation through MCP |
| `test_mcp_llm_answer.py` | Independent MCP → LiteLLM → Ollama → Qwen3 answering |

The independent LLM test does **not** prove ADK delegation.

The multi-agent delegation test does **not** prove independent MCP LLM answering.

They validate two different execution paths.

# 15. Independent MCP LLM Architecture

Current independent answering path:

```text
                ┌─────────────────────┐
                │     MCP Client      │
                └──────────┬──────────┘
                           │
                           │ call_tool
                           │ ask_question
                           v
                ┌─────────────────────┐
                │    MCP Server       │
                │ app/mcp/server.py   │
                └──────────┬──────────┘
                           │
                           v
                ┌─────────────────────┐
                │      LiteLLM        │
                └──────────┬──────────┘
                           │
                           v
                ┌─────────────────────┐
                │       Ollama        │
                │   localhost:11434   │
                └──────────┬──────────┘
                           │
                           v
                ┌─────────────────────┐
                │      Qwen3 8B       │
                └─────────────────────┘
```

This path is intentionally independent from:

```text
root_agent
general_agent
api_agent
mcp_agent
```

# 16. Troubleshooting

## MCP server does not start

Check that the virtual environment is active:

```powershell
.\.venv\Scripts\Activate.ps1
```

Then:

```powershell
python -m app.mcp.server
```

---

## Port 8000 already in use

Find the process:

```powershell
netstat -ano | findstr :8000
```

Stop the application currently using port 8000 before starting MCP.

---

## MCP tests cannot connect

Make sure Terminal 1 is still running:

```powershell
python -m app.mcp.server
```

Then retry:

```powershell
pytest -q tests/integration/test_mcp_integration.py
```

---

## Ollama/model error

Verify Ollama:

```powershell
ollama list
```

Confirm:

```text
qwen3:8b
```

is available.

The MCP LLM answering feature uses the existing configured Ollama endpoint and model.

---

## `ask_question` is not recognized in PowerShell

Do not execute:

```powershell
ask_question("What is law?")
```

Use the MCP client/test instead:

```powershell
python tests/integration/test_mcp_llm_answer.py "What is law?"
```

The MCP layer now supports both:

### Tool-based operations

```text
mcp_health
get_server_time
add_numbers
multiply_numbers
```

### Independent LLM answering

```text
ask_question
```

No ADK agent is required for this independent MCP answering path.
